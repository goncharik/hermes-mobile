# Hermes Mobile — project conventions

Native SwiftUI + TCA iOS companion for a self-hosted Hermes Agent. A thin remote
client; no agent logic on the phone. See `README.md` for the feature overview,
`docs/architecture.md` for structure/protocol/auth/push/hydration detail,
`docs/development.md` for build/test/distribution, and `docs/plans/completed/`
for the full design history. **Per-feature invariants and rationale live in
`docs/features/` — read the matching doc BEFORE touching that feature**; the
bullets below are the compressed rules.

## Layout

- **`HermesKit/`** — local SPM package: all models, dependency clients, and TCA
  reducers. This is where logic lives. Built/tested with `swift test` (no simulator).
- **`HermesMobile/`** — thin app target: SwiftUI views only, generated by Tuist.
  `Project.swift` is the source of truth; the `.xcodeproj`/`.xcworkspace` are
  generated and gitignored.
- **`HermesWidgets/`** — the widget extension (#138); links only HermesKit's Foundation-only
  `HermesWidgetKit` product. Its `Sources/Views/` are compiled into `HermesMobileTests` too.
- **`HermesMobileTests/`** — iOS XCTest target for SwiftUI snapshot tests and view logic
  that needs a real UIKit host (separate from the SPM suite).
- **`Probe/`** — non-shipping harnesses, unreferenced by `Project.swift`: the protocol probe
  (gitignored `Probe/fixtures/`) and the committed `LoopbackSpike/`.

## Core rules (every change)

- **Logic in `HermesKit`, views thin.** Keep view files declarative; push behavior into
  reducers. New testable logic goes in the package, not the app target.
- **Clients are `@DependencyClient` structs** with `liveValue` + a `testValue` (no-op or
  in-memory). Inject `URLSession`/transports for testability. Never call
  `UIKit`/`Security`/`URLSession` directly from a reducer — go through a client.
- **Decode leniently; never crash on unknown events** — unknown `type` → `.unknown`.
- **Gate UI by server capability, not assumptions** — the shared pattern: a JSON-RPC
  `-32601` (`GatewayError.isUnknownMethod`) or REST 404 (405 where an older agent's catch-all
  matches) flips a `*Supported` flag off (attach, profiles, cron jobs, push, slash commands,
  TTS); `?? true` on unknown capability fields. Mirror the desktop's behaviour where one
  exists; check the Hermes source. (#19's OAuth provider buttons deliberately invert `?? true`
  — see the OAuth bullet below.)
- **Surface RPC failures** (set `errorBanner`, clear `isSending`/`activity`) — never
  swallow them with `try?` (the logout hops, below, and the debug-log-only #98 replay read
  and Settings `/api/status` probe are the carved-out exceptions).
- **Commit messages**: capitalized verb, no conventional-commit prefixes, concise.

## Gateway & session lifecycle

- **Gateway socket**: one long-running cancellable effect funnels every frame through
  `.gatewayFrame`; outbound RPCs are discrete one-shot effects. Reconnect/backoff lives
  in the reducer, not the client. Per-request timeout 30s (`GatewayError.timedOut`);
  the slash pipeline uses `HermesGatewayClient.longRunningMethods` → 120s. Reconnect (#98):
  the gated `.ready` replays the gap from the `seq` cursor (`session.events.since`) BEFORE
  the hydrate, no drain/turn-end side effects mid-fold, failure = plain hydrate
  (`docs/architecture.md`).
- **Session-not-found self-heal (#17)**: outbound RPCs re-resume (or `session.create`
  when there's no stored id) then replay the RPC **once** — single retry, no loop, at most
  one heal per user action (`HealCursor`); the banner shows only if the heal also fails.
  The foreground `session.resume` likewise recreates rather than treating it as a benign
  drop. A never-saved session (`awaitsFirstPersist`, #132) falls back from a not-found
  resume to create (`fallbackToCreate`). Details: `docs/architecture.md`.
- **Every outbound frame is encoded by `JSONRPCRequest.wireEncoder`** — its
  `.withoutEscapingSlashes` is LOAD-BEARING: a bare `JSONEncoder` escapes base64 `/` as
  `\/`, making frame size content-dependent (worst case doubled) against uvicorn's
  16 MiB `ws_max_size`, silently killing the socket mid-upload. Never encode a request
  with anything else.
- **Hydration is server-authoritative** via one `hydrate(sessionID)` funnel
  (open/foreground/cold-launch → `.ready` → hydrate): call `session.resume` (NOT
  `session.activate` — live-only, 404s stored sessions) and apply `info` / `running` /
  `inflight` from the response — rebuild rows wholesale, server wins, never merge; seed
  the streaming row from `inflight`. `open_requests` (v7 prompt replay) is reconciled, not
  rebuilt: absence authoritative, whatever `running` says. Exception (#26): a foreground re-hydrate of a
  still-RUNNING turn preserves the client's live reasoning, tool and sealed-commentary rows
  (server `inflight` carries none; the seed gets only the text after the sealed segments); a
  completed turn still replaces wholesale. Details:
  `docs/architecture.md`.
- **Elapsed-timer continuity**: client turn-start anchor persisted in
  `ChatSnapshotClient` (set on `prompt.submit`/`message.start`, cleared on terminals).
  On hydrate, `running` decides whether the timer runs; the anchor only supplies the
  start instant — a stopped turn discards a stale anchor (no phantom timer).
- **A running chat keeps its socket across navigation (#33)**: chat state lives in the
  `AppFeature`-owned live-chat slot (`liveChat` via `.ifLet`); the nav path holds thin
  markers only. Teardown is an `AppFeature` policy — `teardownSlot` = `persistNow` →
  `.teardown` → `.clearLiveChat`; the **nil-out is mandatory** (`ifLet` auto-cancel is
  the only thing that reaches un-ID'd one-shot effects — never just swap slot state).
  Never cancel-and-redial a healthy socket (`connect` only when `status != .ready`).
  View disappearance is `AppFeature.chatViewDisappeared`, handled AFTER the pop
  animation, never at `.popFrom` time. A slot with `hasQueuedWork` stays alive.
- **"Detached" means `isChatDetached` = `layout == .compact && path.isEmpty` (#80)** —
  never a bare `path.isEmpty`. `.regular` needs a regular size class AND the pad idiom (a
  Max iPhone in landscape stays on the stack; Slide Over does too), reported via
  `layoutChanged` and set FIRST so the column-move `chatViewDisappeared` is a no-op. The
  `ChatScreen` marker is COMPACT-ONLY: in regular the slot IS the `NavigationSplitView`
  detail, the path stays empty, and the chat is never detached (no pop/turn-end teardown).
  Regular never shows a blank detail — every seat comes from `detailRefill`; narrowing drops
  an `isPristineNewChat` seat instead of pushing it, and the seat follows the list's profile
  (`profileReseatSignal` — deferred, never dropped, while composer input is in flight or the
  window is narrow). A regular fill dials its chat from the reducer AND
  bumps `slotGeneration`, which the detail view is `.id`-keyed on so nothing leaks between
  sessions. Sidebar highlight is a plain optional (`highlightedSessionID`), never
  `List(selection:)`. Details: `docs/features/ipad-layout.md`.
- **Backgrounding gets ~30s grace** via `BackgroundTaskClient`: running slot →
  `persistNow` + begin; expiry while backgrounded → final persist +
  `.teardownSocketOnly` (state + replay cursor stay in memory for the #98 replay / #26
  catch-up); a stale expiry racing `.active` is a guarded no-op. Every slot first gets
  `.sceneBackgrounded` (stop read-aloud, hold auto-speak); an idle slot then persists only,
  no slot is a no-op — either way no task, no battery burn.
- **Auth has three regimes** (`AuthSession`: `.token` | `.cookie` | `.bearer`). Token mode must
  stay byte-identical to the legacy single-token path (backward-compat guard). Gated modes:
  password-login cookies (refresh is transparent server-side — persist + resend the jar,
  stored in `KeychainClient`) or OAuth bearer tokens (#19), both with a fresh single-use WS
  `?ticket=` minted per connect — never cached, and `.cookie`/`.bearer` SHARE the `connect`
  branch so the cancellation choreography can't drift; a 401 mint → `.sessionExpired` →
  `ReauthFeature` with identity-aware routing (same user reconnects; different user pops +
  clears identity-scoped prefs). Onboarding's Sign in layout is derived from the capability.
  Full protocol: `docs/architecture.md`.
- **`RequestAuth` is the ONE place either auth header is written**, and **every bearer read
  goes through `BearerTokenStore.validAccessToken()`** — the store owns the token pair and is
  the only refresh path; never read the Keychain or `expiresAt` directly. One synchronization
  domain (no state outside its lock, no `await` under it); revocation = DELIBERATE abandonment
  (`clear` requires a `BearerStoreClaim`). Ordering: `rest.logout`/`rest.unregisterPush` BEFORE
  `bearerTokens.clear(claim:)`; `detachPersistence()` BEFORE every `keychain.deleteSession()`.
  `rest.logout` is the one deliberate never-swallow exception. Details:
  `docs/features/oauth-sign-in.md`.
- **An OAuth provider button needs positive evidence, not `?? true`**: an OAuth provider AND
  `native_pkce` in `auth_flows`, else hidden. A gated server with no providers is
  `.tokenOnly` (token layout). Loopback-only redirect (`ASWebAuthenticationSession` + in-app
  `NWListener`), no WKWebView fallback, plain-text provider labels (App Store 5.2.1).
  Details: `docs/features/oauth-sign-in.md`.
- **Onboarding is a `ConnectionPath` stack (#136)**: Welcome (root, no reducer) → `ServerStep`
  → `SignInStep`, parented by `ConnectionFeature`; `.connected` goes up unchanged. Sign in exists
  only with a `ServerProbe` and connects to the URL that answered (the `:9119` fallback is what's
  saved); popping it cancels its effects (that abandons OAuth). Probe failures are a typed
  `ProbeFailure` from `probeStatus` — never widen `RESTError`. Local Network gets a card hint
  line, no explainer or detection (TN3179). Details: `docs/features/onboarding.md`.
- **Login help**: the `AgentSetupGuideView` sheet is the single connection-help surface
  (Welcome, the Server step, each failure card, the retry screen — view-local `@State`, never
  reducer state). Keep the README quick-start (incl. the Hermes Cloud copy) and the sheet
  verbatim-identical.
- **Launch auto-connect failure that isn't a credentials verdict raises the retry screen,
  never onboarding (#62)**: only 401/403 falls back to onboarding (`State(recovering:token:)`:
  auto-probing Server step, token prefilled); everything else (incl. `RESTError.offline`)
  populates `connectionFailed`. `ConnectionFailedFeature.isRetryable` is the ONE routing
  rule. Launch path only; a foreground re-probe supersedes an in-flight one.

## Transcript & chat UI

- **Streaming has no message id** — the fold tracks one in-flight assistant row created
  lazily on the first delta (an empty `message.start` must not render an empty bubble);
  `session_id` is on the event frame. `message.interim` seals it (the next delta starts a
  new row; re-sent seals dedup on `(turn_id, segment)`); a turn's FINAL reply = its last
  assistant row (`turnSpans`) — only it gets the action bar / branch / read-aloud.
- **`thinking.delta` is the spinner, NEVER reasoning** — it replaces `turnActivityLabel`
  (never appended, never in a row). Reasoning = `reasoning.delta`/`.available`, one
  `.reasoning` row per burst. Timer (`turnSeconds`, cancellable `continuousClock`, frozen on
  terminals), spinner label and `turnStatus` caption live on the turn header — never a
  persistent footer above the composer.
- **Tool calls fold (#45/#55)**: pure `TranscriptFold.items` turns rows into display items
  (turn header, run summary, call line, in-place body); a finished turn collapses unless the
  user last expanded it. `FoldExpansion` is keyed by ORDINALS (survives the hydrate id
  rewrite, pruned on hydrate); per-tool titles/bodies/outcomes come from the pure
  `ToolPresentation`; reloaded output is "unavailable", never faked. Details:
  `docs/features/tool-calls.md`.
- **Transcript rows use DETERMINISTIC content-derived IDs** — FNV-1a of
  `(sequenceIndex, role, kindDiscriminator)`; never a random `UUID`, never derived from
  mutable streaming text. Live streaming rows reconcile to the history ID on the next
  hydrate; `message.delta` mutates the row in place, preserving its id.
- **History paginates client-side** (no server pagination): `windowStart` window over
  the full in-memory transcript; hydrate resets the reducer's window to the bottom; the start
  snaps down to a turn's user row (derived, `windowStart` stays raw). An update that keeps old
  rows (`.slide` #125, `.appendOrMutate`) or only changes the fold follows if pinned, else holds
  the reader's topmost surviving item — never a yank; only a `.reset` (no row survives, or the
  window shrank and lost its head) or first population jumps. The pin follows the USER's scroll
  direction (`pinnedAfterUserScroll`), never geometry alone: the keyboard hiding grows the list
  under a reader who scrolled up and must not re-pin them. Mechanics: `apply(items:rowIDs:)`.
- **`CollectionTranscriptView` is the ONLY renderer** — `UICollectionView` + diffable
  data source keyed on the deterministic `TranscriptItem.ID` + `UIHostingConfiguration` cells
  (the pure-SwiftUI engine was removed: it dropped tail messages); open/hydrate/prepend/slide
  classification runs on the RAW window's row ids (`windowRowIDs`, unsnapped), so neither a
  fold change nor the snapped start moving reads as a reset. Stick-to-bottom is
  renderer-local, not reducer state; pure scroll-math helpers stay outside the
  `#if canImport(UIKit)` guard. No diff apply on an unmeasurable view (#128): gated by
  `TranscriptScrollMath.canApplySnapshot`, latest deferred (`docs/features/tool-calls.md`).
- **The empty-chat hero swaps the transcript REGION on `ChatFeature.State.showsEmptyHero`**
  (#80) — a HermesKit predicate (`transcript.isEmpty && !isSending && streamingRowID == nil
  && (storedSessionID == nil || hasHydrated)`), never view-derived. `hasHydrated` is set on
  `applyActivate` AND the `session.create` handshake so a resumed chat waiting on history
  never flashes the hero; `ChatEmptyHeroView` is display-only with ONE tagline constant.
- **The chat column is capped at `ChatLayout.readableMaxWidth` (760) on the OUTER
  container only** — `.frame(maxWidth:)` + `.frame(maxWidth: .infinity)` on `ChatView`'s
  outer `VStack`; phone widths are below it (compact unchanged); never on table cells
  (`CappedWidthLayout` rule stands). Measured in `ChatColumnLayoutTests`.
- **Markdown & tables**: block classification in `MarkdownSegment`, rendered by
  `MarkdownText`; only USER messages get a bubble; wide tables PAN in
  `MarkdownTableView` (direction-aware fade), cells capped by `CappedWidthLayout` —
  never `.frame(maxWidth:)`. Invariants: `docs/features/markdown-rendering.md`;
  measured derivations stay in that file's doc comments.
- **`review.summary` is live-only (#47)** — never in server history; a hydrate wipes
  the row (accepted). Rendered as a bubble-less footnote status row; blank text dropped.
- **Hermes-authored notices (#124)**: history rows with a notice `display_kind`
  (delegation/process results, model/personality switch, resumed or failed turn) rebuild as
  `.status(kind: "notice")` lines, never bubbles; `hidden` / `model_only` rows are dropped.
  Same rule for a running turn's `inflight.display_kind`. Details: `docs/architecture.md`.
- **Message actions & branching (#34)**: copy via the shared
  `copyWithFeedback`/`rowCopyToken` mechanism; branch is a seeded `session.create` (on a
  session-authority host, a fenced `session.mutate` branch that opens by stored id, no seed)
  guarded by strict `canBranch` gates with a client-held `BranchSeed` recovery protocol
  (probe-before-seed-replay; no probe budget). The trickiest state machine in the app —
  read `docs/features/message-actions-and-branching.md` before touching it.
- **Prompt cards (#97)**: v7 prompts are server→client requests in ONE per-slot queue whose
  head is the card, answered via `request.answer` in the request's shape (`expired` → "Already
  handled elsewhere"; card stays until acknowledged); legacy `*.request` events stay as-is.
  **Raise cards through `State.present(_:)`** (token-keyed) — `refreshPresented(_:)` (same srq
  id, no token bump) is the ONE exception. 4404 only window-owned bridges; never answer any
  other unrendered prompt; narrow the server's choices, never widen. Cards are a pinned row
  over ONE `BoundedHeightLayout` region. `GatewayConnection` holds `.ready` until the
  per-socket `client.capabilities` advertisement settles (5 s cap, no retry); its `-32601` is
  NOT a `*Supported` verdict (`docs/architecture.md`). Queue, replay, decline matrix, clarify
  forms, layout, push-tap recovery: `docs/features/approvals.md`.
- **Approval mode is profile-wide**, gated on desktop contract ≥3: reconcile through
  profile-scoped config reads, preserve absent session-info values, and allow one write
  at a time. Details in `docs/features/approval-mode.md`.
- **Context-usage pill**: display derives from `Usage` helpers in HermesKit (thresholds
  mirror the Hermes TUI, unit-tested); severity→color and popover are local `@State`.
- **File references are tappable in place** — `MarkdownText.inline` attaches
  `hermes-file://preview?path=` ONCE: markdown `file:`/abs link targets via
  `FileReference.path(fromLinkTarget:)`, `MEDIA:` tags and bare ASCII absolute paths WITH an
  extension via the pure `FileReferenceScanner` (no relative paths, spaces or inline images).
  `ChatView.openFileReference` is the ONE `openURL` hook, installed on the cell builder AND the
  body. `FilePreviewFeature` is an `@Presents`/`.ifLet` child over `/api/fs/*` (stored id +
  profile, ONE retry on "Session not found"; deliberately NO `*Supported` flip; `session.create`
  unchanged). Details: `docs/features/file-preview.md`.

## Composer & input

- **Voice input**: `AudioRecorderClient` (metering `AsyncStream` drives the waveform) +
  the agent's `POST /api/audio/transcribe` — not on-device `Speech`.
- **Attachments upload BYTES, never device paths** (`image.attach_bytes` / `pdf.attach`
  / `file.attach` before `prompt.submit`). Pickers return a `PickedBatch` (drops
  banner; a cancel is the silent empty batch); every image source goes through
  `PickedImageLoader`; the real size limit is the 16 MiB WS frame. Full pipeline:
  `docs/features/attachments-and-paste.md`.
- **The composer is `ComposerTextView`** (UIKit `UITextView`, not SwiftUI `TextField`)
  so image paste works (#54); Return inserts a newline — the send button is the only
  submit path (#70); deliberately no `@FocusState` on the representable. Paste claiming
  and provider loading rules: `docs/features/attachments-and-paste.md`.
- **Slash commands (#36)** go through `slash.exec` → `command.dispatch`, never as
  prompt text. Submit takes the command path only when the text is command-shaped
  (`SlashSuggestionFilter.isCommandShaped`), no attachments are staged, AND the parsed
  name resolves in the curated catalog — anything else falls through to plain
  `prompt.submit` (never destroy the composer text). `slashExecInFlight` holds the
  composer lock (with `!isSending` in `canSend`); the post-command refresh is a full
  server-authoritative hydrate. Pipeline, directives, no-fallback carve-outs, known
  limitations: `docs/features/slash-commands.md`.
- **Mid-turn prompt queuing is client-side (#66)** — never submit against a running
  turn. Everything funnels through `submitDraft` + `drainQueueIfReady`; Stop and turn
  `.error` park the queue; a failed drain re-parks at head (never silently lost, never
  shown twice); queue is in-memory only. Carve-out: Steer now sends a queued entry with
  `session.steer` (never `prompt.submit`); it stays queued under `steeringEntryID`, which
  holds the drain, and leaves only on `status == "queued"` (or a hydrate proving a lost accept
  delivered it). Details:
  `docs/features/prompt-queue.md`.
- **The `model · effort` chip is the only picker (#81)** — `config.set` inside the #17 heal,
  optimistic then reconciled by `session.info`. Offer the FULL reasoning ladder always (the
  server clamps per provider and publishes no per-model list); a failure rolls back BOTH keys
  + banners, and only the 4002 `unknown reasoning value` verdict latches the per-slot, unpersisted
  `extendedReasoningSupported`. The sheet (#130) is the `@Presents` `ModelPickerFeature` (load +
  favorites/collapse prefs; picks go to the parent by delegate) over the pure `ModelPickerLayout`.
  Fetch is `explicit_only`; the checkmark matches `(provider, model)` and the provider
  follows/rolls back with the pick. Details: `docs/features/model-picker.md`.
- **Read replies aloud (#74)**: the toggle is a device-local pref, never `voice.auto_tts`.
  Synthesis is `POST /api/audio/speak` only; `TTSClient` is a dumb player and the state
  machine is per-slot in `ChatFeature`. A completed-FINAL-reply anchor (armed, re-based on every
  hydrate; interim segments never count) decides what is pending; a #98 replayed completion is never read. Only USER
  submits and the mic barge in (the mic `await`s `tts.stop()` BEFORE `requestPermission`);
  every regular `prompt.submit` takes the 120 s `interrupted` latch. A 404/405 hides both
  controls. Details: `docs/features/read-aloud.md`.

## Session list

- **Working glow is event-driven** (`ChatFeature.Delegate.runningChanged`); the poll is
  only a backstop, and a cached running-guess must never start a glow on its own.
- **`ChatSnapshotClient` (GRDB) is a NON-AUTHORITATIVE cache** — instant paint + turn
  anchor only; server wins on hydrate, persistence debounced (flushed on
  `.background`), wiped on logout; behind the client boundary (no reactive `@FetchAll`).
- **Persistence**: secrets → `KeychainClient`; non-secret prefs (URL, seen counts, pins,
  swipe default, read-aloud toggle, profile, model-picker favorites/collapsed providers,
  push-card snooze, tips dismissal) → `PreferencesClient`. Clients over `@Shared` for test
  isolation; both have `.inMemory()`. **Logout must clear every prefs entry.**
- **Pin membership syncs with the server; pin order stays device-local.** Details in
  `docs/features/session-list.md`.
- **Archive, rename, and delete are server-side**, optimistic with rollback (list → REST
  `PATCH`/`DELETE`; chat rename → `session.title`). Every session `PATCH`/`DELETE` goes
  through `mutateSession`: a `mutation-snapshot` read, then the write fenced with
  `request_id` + `expected_revision` (v0.22.1+ refuses unfenced writes with 409), unfenced
  only when the snapshot route is missing. Details: `docs/features/session-list.md`.
- **Delete (#73) mirrors archive** (`deletingIDs` guard, rollback) with a
  `deleteSupported` flip on 404 **or 405** (older agents serve the path for
  `PATCH`/`GET`) — silent, mirrored both ways with the archived sheet; the swipe-default
  pref (`SessionSwipeAction`, logout-cleared) clamps to Archive via
  `effectiveSwipeAction` when unsupported. Slot delete tears down with
  `teardownSlot(flushSnapshot: false)` + snapshot wipe (flush would re-save it); archive
  and delete both refill the regular-width detail (`thenFill: detailRefill`); the
  approval-badge entry clears only on the CONFIRMED delete (`sessionDeleteSucceeded`).
  Archived-sheet delete is immediate — no confirmation (deliberate) — and its DELETE
  round-trip runs in the parent list (a presented sheet's effects die on dismissal).
  A destructive success restarts (not bare-cancels) a pending fetch; a failure after a
  profile switch drops the rollback re-insert. Details: `docs/features/session-list.md`.
- **Chat ⋯ menu Archive/Delete**: rules in `docs/features/session-list.md`.
- **Date sections, inbox cards, cron jobs, and branch nesting are display-only** over one
  array fetched as TWO source slices (interactive + cron, never one shared page — cron runs
  starve it): update-date sections via pure `SessionDateBucket` / `groupEntriesByDate`;
  `SessionCardView` on every interactive row, compact `SessionRowView` only for the flat cron
  fallback + archived sheet; the Cron Jobs TAB lists jobs (tab only with cron content; views
  read `effectiveTab`; no badge; search is Sessions-only). **Never group cron runs by session
  id** — an expanded job's runs come from `/runs` (its 404 flips no flag). Nesting via
  pure `flattenSessionsWithBranches` (orphans de-nest). Details: `docs/features/session-list.md`.
- **Row affordances**: trailing swipe = destructive default FIRST (full-swipe target),
  then Rename; context menu always offers both Archive and Delete (gated); Copy ID
  context-menu-only; rows are natural-height — NO min-height floor (a floor for
  icon-over-label swipe buttons was tried twice and reverted as too tall, #79);
  animations respect reduce-motion. Confirmations follow the
  destructive-actions idiom below (`ConfirmationDialogState` + `.bottomActionSheet`).

## UI idioms

- **Auto-poll**: cancellable `continuousClock` sleep-loop started on `.task`, cancelled
  by an explicit `.onDisappear` action (not bare `.task` cancellation; on a pushed stack
  screen the stack's own cancellation replaces it); paused while searching; `TestClock`-drivable.
- **Destructive actions** use TCA `ConfirmationDialogState` (`@Presents`) so
  confirm/cancel is state-driven and unit-testable — but present it via
  `.bottomActionSheet`, never `.confirmationDialog`: iOS 26 renders the system
  dialog as a title-less popover (FB20644893).
- **Transient toasts live in the reducer**: a per-copy token (`Int?`, not `Bool` — every
  copy bumps it) + a `cancelInFlight` clock dwell effect (`copiedFeedbackDuration`),
  duplicated per feature. Attach the overlay where nothing can swallow it (before a
  bottom `.safeAreaInset`; on the transcript, not the outer `VStack`); announce every
  copy to VoiceOver off the token.
- **Settings is a home TAB: ONE `Form` (six groups) + a `SettingsPath` stack** owned by
  `SettingsView`, layered over the WHOLE split view in `AppView` (never inside a column — that
  nests stacks); state seeded on select, dropped on leave (`closeSettingsTab()`); every chat
  route (push tap, intent, open, new session) leaves the tab. Rows
  push by reducer append, never `NavigationLink`.
  App icons: every set is an alternate in `Project.swift` (primary included — it differs
  per build); `AppIconCatalog.parse` filters the primary, which is always `set(nil)`; iOS
  persists the choice, logout never touches it. `DiagnosticsReport` takes no `AuthSession`
  (no-secrets invariant). Gates, icon table, links: `docs/features/settings.md`.
- **The agent updater (Settings → Server, under Agent) POSTs `/api/hermes/update` at most
  once per confirmation and never retries it**; a send-side failure or 5xx is `.uncertain`. Only a
  finished receipt proven to be this phone's run (its action id) reports success; a
  reconnect never does. Contract: `docs/features/agent-update.md`.

## Push notifications

- Three artifacts; only the iOS app is in this repo (plugin + gateway are separate
  repos). Non-negotiables: capability-gate on the plugin `/register` 404; the
  **generic-body privacy rule** (no content/args/command in a push, ever); `apns_env`
  must match the per-configuration `$(APS_ENVIRONMENT)` entitlement; the app and plugin
  hold no push secret (gateway-issued device-scoped capability); the permission prompt fires
  only from the session list's Turn on card, never on appearance (#136,
  `docs/features/onboarding.md`). Repos, capability scheme, the four trigger hooks,
  cold-launch tap replay (#46), and fork filtering (#64):
  `docs/features/push-notifications.md`.
- **Push-tap routing dedups against the slot (#32)** under `isChatDetached`: matches slot
  and not detached (compact marker on top, or any slot in regular) → in-place hydrate, no
  navigation; matches a detached slot (compact only) → push marker + `.reattached`;
  different session → replace slot + SET the path (single new marker in compact, empty in
  regular; never stack). Cold-launch taps replay through this same path.
- **App Intents and quick actions (#93) only route** (quick actions = dynamic shortcut items
  set via `QuickActionsClient` only while signed in, routed by `QuickActionSceneDelegate`; App
  Shortcuts never reach the long-press menu): `LaunchIntentBridge` → `launchIntentReceived` → the
  "New session" `reduceCreateSession` (busy slot silently replaced). Pre-home intents stash
  last-wins with `pendingPushTap`, replay in `landOnHome` (the launch action only on the launch
  auto-connect landing), clear on logout; `pendingLaunchAction` (dictation / camera / photos) is
  a one-shot consumed at the slot's first start (or at once on a reused seat), the mic
  idle-only. Details: `docs/features/app-intents.md`.
- **Widgets, controls and the Live Activity (#138) are thin**: the `HermesWidgets` extension
  links ONLY the Foundation-only `HermesWidgetKit` (no network, no Keychain); every tap is a
  `hermesmobile://` URL → `LaunchIntentBridge.received(url:)` (`.openSession` = push-tap
  routing, server-guarded stash). Content derives ONLY from the `agentStatus` edge
  (`.onChange(of: \.agentStatusInputs)`; nil = hold, never end); scene edges only restamp,
  toggle-off / landing sweep / logout only end or clear. Both the App Group mirror and the
  aggregate activity (foreground-only start) are stamped `freshUntil` (8 h foreground, ≤ 40 s
  backgrounded → "Outdated"); a backgrounded turn-end push (`content-available` wake) marks its
  session finished. Details: `docs/features/widgets.md`.

## Multi-profile

- Device-local with per-call scoping: the selected profile *name* persists in
  `PreferencesClient`; never `POST /api/profiles/active` (mutates the server default
  for all clients). Thread the literal name (incl. `"default"`) into `session.create`/
  `resume` and session-scoped REST when the profiles API exists, else omit it — omitted =
  the server's LAUNCH profile, not `"default"` (#114). Search is scoped too (as on desktop).
  Add-profile is create-then-PUT-soul; selector capability-gated; no per-profile color.
  Profile comparison and the persisted capability verdict: `docs/architecture.md`.

## Testing (required for every change)

- TCA reducers: `TestStore` + `@Dependency` overrides + `TestClock`. Event-reduction
  tests are the highest-value suite.
- `swift test` buffers when piped — use `script -q /dev/null swift test --package-path
  HermesKit` for live output (or `make test`).
- Snapshot tests: `make snapshot` (assert) / `make snapshot-record` (re-record — it
  `rm -rf`s the whole `__Snapshots__` dir; use only for a deliberate global re-render).
  To add ONE new snapshot test, run `make snapshot` twice (first records + fails by
  design, second asserts clean). Row timestamps (and the list's section calendar) are
  pinned for determinism — `docs/development.md`.
- **A snapshot of a SCROLLABLE view must pin an explicit size along its scroll axis** —
  `componentImage()` renders at `.sizeThatFits`, and a `ScrollView` offered nothing
  records a blank sliver. Pin both width and height for a vertical one.
- **A `List` cannot be component-rendered at all** — `componentImage()` paints its section
  headers and FAB but NO rows, and ignores the dark trait; list snapshots use
  `deviceImage()` (both helpers take an `appearance:`; `deviceImage(height:)` for a tall list).
- **Layout facts a snapshot cannot prove go in a measured `UIWindow`-hosted XCTest**
  (assert `contentSize` vs `bounds`, hosted `sizeThatFits`) — see
  `MarkdownTableLayoutTests.swift` and `ApprovalCardLayoutTests.swift`. Pin
  `.dynamicTypeSize(.large)`, and vary it where a `@ScaledMetric` cap is under test.
- **`make snapshot` is clean** (407/407), so any failure is a real signal. A view change
  re-records its own baselines in the same PR. If a future runtime drifts, judge by size
  first: differing render size = regression; equal size with small pixel residual = drift,
  re-recorded in its own commit. Details: `docs/development.md`.

## Gotchas

- **A `.task` on a `NavigationStack`'s ROOT view re-fires on every pop back to it** — put
  once-per-presentation work (probes) on the `NavigationStack` itself (see `SettingsView`).
- **Tuist only forwards `TUIST_`-prefixed env vars** to the manifest; run scripts
  translate friendly names. For direct `tuist generate`, use `TUIST_DEVELOPMENT_TEAM` /
  `TUIST_SERVER_URL`.
- **New source files need `tuist generate`** before an `xcodebuild` app build picks
  them up (sources are globbed at generation time).
- **A `ScrollView` handed a concrete proposal along its scroll axis swallows it
  whole** — it reports the proposal, not its content, so `min(content, cap)` regions
  must probe with that dimension unspecified (custom `Layout`); see
  `BoundedHeightLayout.swift`.
- **`@Sendable` effect closures** must capture dependencies explicitly (`[gateway]`) —
  the reducer `self` is not `Sendable`.
- **Deployment target is iOS 18**. Gate genuinely-newer APIs:
  `#available(iOS 26, *)` for Liquid Glass with a material fallback.
- **A `public struct` nested in feature State** needs an explicit `public init` to be
  constructed from the app/snapshot target.
- **HermesKit is tested on macOS via `swift test`** — guard iOS-only client
  `liveValue`s with `#if canImport(UIKit)` (non-iOS `liveValue = testValue`) and keep
  pure logic outside the guard so it stays unit-tested.
- TestFlight **export must use manual signing** (cloud/API-key signing fails on export).
